# My_PID_Motor v2.2 status 与 run/stop 行为回归计划

> 当前文档只是测试计划，不代表回归已经执行或通过。

## 1. 测试目标

联合验证：

1. `status` 输出字段齐全、顺序与格式稳定；
2. stop 后处于安全软件状态；
3. `run=1` 后进入运行状态；
4. stop 后能够再次启动；
5. 第二次 stop 后再次回到安全软件状态。

## 2. 前置条件

- 使用真实 CRLF，保存完整 TX/RX；
- 电机、驱动板和电机供电连接正常；
- 使用 UART 目标源，target=600；
- 使用 `kp=0.05,ki=0,kd=0`；
- 每条控制命令后等待约 300 ms 再查询 status，避免只看到入队状态；
- 不施加人工负载，不做正反转直接切换，不做 ADC target 测试；
- 如出现异常声音、发热、剧烈抖动或 fault，立即发送 `stop` 并保存日志。

## 3. 串口命令序列

```text
stop
status
set target uart
kp=0.05
ki=0
kd=0
t=600
status

run=1
等待约 2 秒
status

stop
等待约 500 ms
status

run=1
等待约 2 秒
status

stop
等待约 500 ms
status
get fault
```

## 4. 期望输出

### 4.1 status 字段

每条 status 应为一条 CRLF 结束的文本行，并按当前格式包含以下 14 个字段：

```text
ms,enable,State,source,target,actual,delta,PWM,adc1,adc2,fault,kp,ki,kd
```

字段名、大小写、分隔符和顺序应保持稳定。`kp/ki/kd` 当前输出为 3 位小数。

### 4.2 状态阶段

| 阶段 | 关键期望 |
| --- | --- |
| 初始 stop 后 | `enable:0,State:IDLE,PWM:0` |
| 设定 target 后、未 run | `source:Uart,target:600,enable:0,State:IDLE,PWM:0` |
| 第一次 run 后 | `enable:1,State:RUN,source:Uart,target:600,fault:NONE` |
| 第一次 stop 后 | `enable:0,State:IDLE,PWM:0` |
| 第二次 run 后 | 再次出现 `enable:1,State:RUN`，串口继续响应 |
| 最终 stop 后 | `enable:0,State:IDLE,PWM:0` |
| 最终 `get fault` | 若全程无 fault，预期 `FAULT_SNAPSHOT_NONE` |

运行阶段的 actual 和 PWM 只要求可解释且方向匹配，不在本计划中规定精确数值。`OK:CMD_QUEUED` 只表示入队，后续 status 才用于确认执行后的软件状态。

以上是期望输出，不是实测结论。

## 6. PASS / FAIL 判定规则

### PASS

- 所有 status 行均包含 14 个字段，字段名、顺序和基本格式一致；
- 两次 run 后均进入 `enable:1,State:RUN`；
- 两次 stop 后均进入 `enable:0,State:IDLE,PWM:0`；
- target/source/PID 没有意外改变；
- 全程没有不可解释 fault、复位、串口失联或状态矛盾；
- 最终原始日志完整。

### FAIL

- status 缺字段、字段重命名、顺序或分隔格式不稳定且未有协议变更说明；
- run 后 enable/State 不进入运行状态；
- stop 后 enable 未清零、State 未回 IDLE 或 PWM 非 0；
- 第一次 stop 后无法再次启动；
- 出现不可解释 fault、复位、状态倒退或 status 无响应；
- 缺少关键阶段 status，导致证据不足。

## 7. 不能外推的边界

本计划只能验证串口可见的软件状态与命令边界，不能证明 PA8 物理 PWM 已归零、方向脚电平、电机电流、真实转矩、制动距离、长期启停寿命或硬件级功能安全。它也不验证负载扰动、正反转直接切换、ADC target、控制带宽或精确动态性能。
