# My_PID_Motor v2.2 参数持久化测试计划

> 当前文档只是测试计划，不代表参数持久化已经实现或测试已经执行。

## 1. 测试目标

验证参数能够按已确认协议保存、显式加载、复位后恢复，并能恢复固件默认值；存储操作不得意外启动电机、改变 fault 或破坏软件状态。

持久化字段固定为 `kp/ki/kd`。非默认 Ki/Kd 仅作为存储标记，测试全程保持 stop，不做 Ki/Kd 控制效果调参。

以下字段明确不持久化：`target/source`、`enable/State`、`actual/PWM/fault`、`adc1/adc2` 以及任何运行态 status 字段。

## 2. 前置条件

- 使用 UART 目标源和真实 CRLF；
- 电机保持停止，测试期间不发送 `run=1`；
- 记录固件 commit、持久化数据版本、存储区域和擦写策略；
- v2.2 正式命令已经冻结为 `save params`、`load params`、`reset params`；
- 正式返回协议已经冻结，执行前确认待测固件声称实现的是同一协议；
- 当前默认 PID 预期为 `kp=0.050,ki=0.000,kd=0.000`，执行前仍须以当前代码/构建记录复核。

## 3. 串口命令序列

### PP-001 保存并在复位后恢复

```text
stop
status
kp=0.06
ki=0.01
kd=0.02
status
save params
rst
等待串口重新连接
status
```

### PP-002 显式加载覆盖未保存的运行时参数

```text
stop
kp=0.07
ki=0.03
kd=0.04
status
load params
status
```

### PP-003 恢复默认值并验证复位保持

```text
stop
reset params
status
rst
等待串口重新连接
status
```

`reset params` 的冻结语义是恢复固件默认 `kp/ki/kd` 并立即写入非易失存储，不存在“仅恢复 RAM”的同名语义。

## 4. 期望输出

- `stop`、PID 设置命令若经当前控制队列处理，预期返回 `OK:CMD_QUEUED`；该返回不等于已经保存到非易失存储；
- `save params` 成功返回 `OK:PARAMS_SAVED`，保存失败返回 `ERR:PARAMS_SAVE_FAILED`；
- `load params` 成功返回 `OK:PARAMS_LOADED`，加载失败返回 `ERR:PARAMS_LOAD_FAILED`；
- `reset params` 成功返回 `OK:PARAMS_RESET`；因写入非易失存储失败而不能完成时返回 `ERR:PARAMS_SAVE_FAILED`；
- 不符合冻结语法的命令返回 `ERR:BAD_CMD`；
- PP-001 复位后的 status 应显示保存值 `kp=0.060,ki=0.010,kd=0.020`；
- PP-002 加载后的 status 应回到 PP-001 已保存值，而不是未保存的运行时标记值；
- PP-003 恢复默认和再次复位后的 status 应显示经代码复核的默认值；
- 全程应保持 `enable:0`、`State:IDLE`、`PWM:0`；未主动制造故障时应保持 `fault:NONE`；
- `rst` 前的应答可能因立即复位而不完整，最终判据以重新连接后的 status 为准。

以上均为期望行为，不是已完成的实测结论。

## 6. PASS / FAIL 判定规则

### PASS

- 三条正式命令及其返回文本与冻结协议一致；
- 保存值在复位后准确恢复；
- 显式加载能够覆盖未保存的运行时修改；
- 恢复默认值在当前定义的持久化语义下正确，并在复位后保持；
- 每次操作后的 status 字段可解释，且全程没有意外启动、PWM 非零或不可解释 fault；
- 原始日志完整保存。

### FAIL

- 保存成功应答后复位丢失参数；
- 加载得到错误、部分更新或跨字段混合值；
- 恢复默认值与代码确认的默认值不一致；
- 存储操作导致 enable、State、PWM 或 fault 出现不可解释变化；
- 出现存储错误但协议仍报告成功；
- 缺少复位后 status 或原始日志，无法确认结果。

## 7. 不能外推的边界

本测试不验证 Flash 寿命、突然断电原子性、CRC 损坏恢复、跨版本迁移或工业级可靠性，也不能证明批量生产一致性和所有参数组合安全。若要验证断电、坏页、CRC 或版本升级，必须另立故障安全测试计划；本轮不通过破坏性操作补齐。
