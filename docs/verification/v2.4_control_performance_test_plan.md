# v2.4.1 控制性能基线测试计划

## 1. 测试目标

在不修改当前 PID 算法的前提下，测量 UART 目标源下的阶跃响应和稳态表现，形成 v2.4 后续算法决策的基线证据。

本计划第一轮只使用：

```text
Kp=0.05, Ki=0, Kd=0
source=Uart
```

## 2. 前置条件

- 使用 v2.4 分支当前固件并记录 commit；
- 电机固定、空载、供电稳定；
- 串口：115200 / 8N1 / CRLF；
- 使用当前 `status` 命令采样，保留完整 TX/RX 原始日志；
- 测试期间保持断电或人工 stop 手段可用；
- 如出现异常声音、剧烈振动、发热、失控或 fault，立即发送 `stop`，必要时断电。

## 3. 第一轮命令流程

```text
stop
set target uart
kp=0.05
ki=0
kd=0
t=500
status
run=1
等待稳定
```

脚本随后自动执行三个阶段：

```text
阶段 A：target=500，记录稳定基线
阶段 B：target=800，记录阶跃上升响应
阶段 C：target=500，记录阶跃下降响应
```

每个阶段约 5 秒，目标采样间隔约 100 ms。结束后：

```text
stop
status
get fault
```

## 4. 原始日志要求

每条 TX/RX 必须保留：主机时间戳、固件 `ms`、`target`、`actual`、`PWM`、`State`、`enable`、`fault`、`kp/ki/kd`、阶段标记和脚本参数。

原始日志路径：`logs/v2.4_step_response_raw_YYYYMMDD_HHMMSS.txt`

## 5. 指标计算

### 5.1 稳态误差

对每个阶段最后 1 秒的 `actual` 求平均值：

```text
steady_error = mean(actual_last_1s) - target
```

报告中同时列出样本数、平均值、最小值和最大值。

### 5.2 超调

对 `500 -> 800`：

```text
overshoot = max(actual_after_step) - 800
overshoot_rate = overshoot / (800 - 500)
```

对 `800 -> 500` 使用同样的绝对方向口径，不能把负向响应直接按正向公式套用。

### 5.3 上升时间和调节时间

以阶跃前稳定值和新目标值定义 10%/90% 交叉点，使用 `ms` 计算上升时间。调节时间从阶跃发生起，寻找最后一次离开目标误差带的时间；默认误差带为目标绝对误差 ±10%。若采样窗口内始终未稳定，记为“未在窗口内调节”。

当前编码器测速存在量化误差，因此不能使用过窄误差带，也不能把一次 `actual` 跳变直接解释成真实机械速度突变。

## 6. 判定原则

第一轮不预设“超调必须为 0”或固定工业动态指标，主要产物是可信基线：日志完整、阶段切换可定位、指标定义可复核、状态和 fault 可解释、结果能指导下一步是否做目标斜坡或抗积分饱和。

若出现控制失稳、不可解释 fault、stop 失效或日志缺失，则测试 FAIL；若只是性能指标不理想，记录为性能问题，进入后续控制改进，不把它和测试链路失败混为一谈。

## 7. 后续顺序与边界

完成基线后，只选择一个方向：阶跃冲击明显时优先评估目标斜坡；启用 Ki 后出现饱和退出慢时优先评估抗积分饱和。两个方向不能在同一轮实验中同时改变。

本计划不验证电流、温升、转矩、物理 PWM 波形、工业级动态性能或功能安全。编码器测速量化、人工空载条件和串口采样间隔必须在最终报告中保留。
