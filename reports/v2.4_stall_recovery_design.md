# v2.4 运行中停转重启辅助设计

## 1. 问题定义

当前控制器在 `RUN` 状态下将目标从 800 降到 500 时，可能出现以下序列：

1. 目标下降使前馈和比例项暂时减小；
2. 电机速度下降，甚至短暂停转或编码器暂时没有脉冲；
3. 停转后普通输出约为 `53 + 0.125 × 500 + 0.05 × 500 ≈ 140`；
4. 该输出可能不足以重新克服静摩擦；
5. 控制器保持 `RUN`，但电机无法自行恢复。

启动 boost 能够把电机重新推起来，但“同方向改目标就 boost”不是正式方案：它会把普通调速命令和重新启动混在一起，也可能让无实际变化的目标命令产生冲击。

## 2. 设计目标

- 保留现有的启动 boost 和反向切换 boost 语义；
- 只有在“系统要求运行、目标非零、实际速度持续接近零”时才触发恢复；
- 恢复过程是一次有限时长、有限次数的动作；
- 恢复成功后回到正常控制；
- 恢复失败时保留证据，并进入保护路径，不能无限重复大 PWM；
- `stop`、目标为零、反向切换和故障都能清除恢复状态。

## 3. 建议状态

```c
typedef enum
{
    CONTROL_RECOVERY_DISARMED = 0,
    CONTROL_RECOVERY_ARMED,
    CONTROL_RECOVERY_CANDIDATE,
    CONTROL_RECOVERY_BOOST,
    CONTROL_RECOVERY_VERIFY,
    CONTROL_RECOVERY_LOCKOUT
} Control_RecoveryState_t;
```

状态含义：

- `DISARMED`：未运行、目标为零或已有故障；
- `ARMED`：允许检测运行中停转；
- `CANDIDATE`：低速/无脉冲条件连续满足，准备触发恢复；
- `BOOST`：执行一次短时恢复 boost；
- `VERIFY`：观察编码器是否恢复；
- `LOCKOUT`：本轮运行恢复失败，禁止无限重复 boost，等待 stop 或故障处理。

## 4. 推荐参数

第一版先使用宏，便于测试调参，不直接写死在控制函数中：

```c
#define APP_STALL_RECOVERY_SPEED_EPS       5
#define APP_STALL_RECOVERY_DETECT_TICK     10   /* 100 ms */
#define APP_STALL_RECOVERY_BOOST_TICK      3    /* 30 ms */
#define APP_STALL_RECOVERY_VERIFY_TICK     20   /* 200 ms */
#define APP_STALL_RECOVERY_MAX_ATTEMPT     2
#define APP_STALL_RECOVERY_ARM_DELAY_TICK  20   /* 200 ms */
```

当前 `FAULT_ENCODER_LOST` 的触发条件还要求 PWM 大于 `MOTOR_PWM_ABS_MAX / 2`。本次异常样本中的 PWM 约为 140，因此不能依赖现有故障检测自动发现这种“低 PWM、目标非零、无运动”情况。正式实现需要在恢复失败后明确进入保护路径；推荐新增 `FAULT_STALL_RECOVERY_FAILED`，而不是把所有情况都误命名为编码器丢失。

`APP_PWM_START_BOOST` 可以复用为第一轮恢复 boost；如果实机出现冲击，再拆出较小的 `APP_PWM_RECOVERY_BOOST`，不要一开始同时改变多个变量。

## 5. 触发条件

恢复检测只在以下条件全部满足时运行：

```text
enable == 1
state == SYS_RUN
target_speed != 0
abs(target_speed) >= APP_TARGET_SPEED_MIN_RUN
abs(actual_speed) <= APP_STALL_RECOVERY_SPEED_EPS
encoder_delta == 0
```

这些条件连续满足 `APP_STALL_RECOVERY_DETECT_TICK` 次后，进入 `CANDIDATE` 并保存一次恢复前快照。

必须在启动 boost 和目标切换后的 arm delay 期间屏蔽检测，避免把正常启动过程或测速窗口初始化误判为停转。

## 6. 恢复流程

```text
RUN/ARMED
   │ 低速无脉冲持续 100 ms
   ▼
CANDIDATE ──保存 target/actual/delta/PWM/attempt 快照──┐
                                                       ▼
                                                    BOOST
                                                       │ 30 ms
                                                       ▼
                                                    VERIFY
                                  actual 或 encoder_delta 恢复 ──► ARMED
                                  超时且 attempt < 2 ───────────► CANDIDATE
                                  超时且 attempt >= 2 ─────────► LOCKOUT
```

`BOOST` 阶段每个控制周期都应明确设置方向一致的临时 PWM，并重置 PID；结束后必须清除 boost 标志，回到普通前馈 + PID。

`LOCKOUT` 不再无限重复 900 PWM。第一版可以先记录 `recovery_failed` 并保持当前故障保护策略；确认测试稳定后，再决定是否映射为 `FAULT_ENCODER_LOST` 或新增独立的 `FAULT_STALL_RECOVERY_FAILED`。

如果决定进入独立故障，建议在 `Control.h`、串口 fault 文本、故障快照和测试报告中同步增加该枚举值；如果暂时不增加故障枚举，也至少要让 `LOCKOUT` 清晰地禁止后续自动 boost，并通过诊断日志报告失败原因。

## 7. 与现有逻辑的关系

- `old_sign != new_sign`：继续负责反向目标切换时的 PID reset 和启动 boost；
- `Control_SetEnable(1)`：继续负责停止后重新运行时的启动 boost；
- 新恢复状态机：只负责运行中已经失去运动/反馈后的有限次自救；
- 不把“同向目标变化”直接等价为“必须 boost”。

## 8. 第一版实现边界

第一版只增加状态、计数器、恢复前快照和必要日志，不同时修改 PID 参数、前馈参数、编码器测速算法和故障阈值。这样可以把“恢复机制是否有效”和“控制器参数是否变化”分开验证。
