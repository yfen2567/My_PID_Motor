# v2.3.1 M3 命令压力时序报告

## 1. 测试结论

**PASS（限定于 50 条、20 ms 间隔的命令压力）**

本次在电机保持停止的条件下，交替发送 50 条 `t=500` / `t=600` 命令，验证命令解析、控制命令队列、对象池、异步 UART 回执和时序观测链路在正常压力下没有出现可见错误。

## 3. 测试过程

前置基线：

```text
stop
set target uart
t=600
status
timing stats
comm stats
```

压力阶段交替发送：

```text
t=500
t=600
t=500
t=600
...
```

共 50 条，随后等待队列和 UART 回执排空，再发送 `timing stats`、`comm stats`、`status` 和 `stop`。

## 4. 回执与状态结果

脚本记录：

- `TX_BURST t=500`：25 条；
- `TX_BURST t=600`：25 条；
- 压力阶段对应的 `OK:TARGET_SET`：50 条；
- 测试结束时 `enable=0, State=IDLE, PWM=0, fault=NONE`。

日志中出现的第 51 条 `OK:TARGET_SET` 属于压力阶段之前的基线命令，不计入 50 条压力命令。

## 5. 时序与通信结果

压力前后 `TIMING_STATS` 均保持稳定：

- `period_us`：约 `9999～10000`；
- `exec_us=20`；
- `tick_exec_us=14`；
- `timeout_count=0`。

最终 `comm stats`：

```text
rx_overflow:0
line_q_full:0
cmd_q_full:0
pool_fail:0
tx_drop:0
tx_error:0
rx_restart_fail:0
```

## 6. 问题分析与边界

M3 证明当前命令速率和数量下，命令链路没有出现可见丢失、队列满、对象池耗尽、TX 错误或时序恶化。它不是队列容量极限测试：命令间隔为 20 ms，且日志中的 `cmd_q` 没有达到满载。因此不能由本次结果外推到更高输入速率、连续无间隔发送或 100 条以上压力。
