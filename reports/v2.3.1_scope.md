# v2.3.1 Timing Observability 范围说明

## 1. 版本目标

v2.3.1 的目标是让 ControlTask 的调度周期、任务执行负载和 `Control_Tick10ms()` 执行负载可观测，并能通过串口和 GPIO 观测接口支持后续定位。

## 2. 当前实现字段

`TIMING_STATS` 现在包含两类信息：

### 当前样本

- `period_us`：最近一次有效控制周期；
- `exec_us`：最近一次完整 ControlTask 执行时间；
- `tick_exec_us`：最近一次 `Control_Tick10ms()` 执行时间；
- `timeout_count`：超过当前 `10010 us` 容差阈值的累计次数。

### 累计聚合

- `sample_count`：自 ControlTask 产生第一份有效样本以来的有效样本数；
- `period_min_us` / `period_max_us`：有效样本中的周期最小值和最大值；
- `max_abs_jitter_us`：相对于标称 `10000 us` 周期的最大绝对偏差；
- `exec_min_us` / `exec_max_us`：完整 ControlTask 执行时间范围；
- `tick_exec_min_us` / `tick_exec_max_us`：`Control_Tick10ms()` 执行时间范围。

聚合统计由 ControlTask 在周期边界处更新，并通过临界区整体复制到时序快照；查询端只读取完整快照。`sample_count=0` 表示尚未产生有效时序样本。

## 3. 与 M0-M3 历史实测的关系

M0-M3 已完成的实机日志是在新增聚合字段之前生成的，日志格式只包含：

```text
period_us, exec_us, tick_exec_us, timeout_count
```

本次新增字段属于代码能力增强，按用户决定不回溯重跑 M0-M3。因此：

- M0-M3 报告仍然有效，但只证明旧四字段和对应测试范围；
- 新增的 `sample_count`、min/max 和 `max_abs_jitter_us` 已通过独立聚合字段冒烟验证，但未纳入 M0-M3 的全量运行/压力回归；
- 如果后续要求完整聚合字段在 IDLE、运行和压力场景下都具备独立证据，仍需重新安排相应回归。

## 4. M0-M4 状态

| 项目 | 状态 | 说明 |
| --- | --- | --- |
| M0 | PASS | 旧四字段的观测链路冒烟通过 |
| M1 | PASS | 旧四字段的 IDLE 基线通过；使用 `10010 us` 容差 |
| M2 | PASS | 旧四字段的电机运行时序通过 |
| M3 | PASS | 旧四字段的 50 条命令压力回归通过 |
| M4 | DEFERRED | 无逻辑分析仪/示波器，GPIO 波形未验证 |

## 5. 不可外推边界

本版本仍不证明逻辑分析仪可见的 PA5/PA6 波形、极限队列压力、长时间稳定性、复杂负载、ADC target 专项行为或工业级实时性。新增聚合字段也不能替代 M4 的外部时序证据。
